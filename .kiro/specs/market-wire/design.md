# Market Wire design

Use a TypeScript service with PostgreSQL. Use the same domain commands for browser, simulated SMS, test MCP and a separately configured Android gateway. Store session ownership, request revisions, offer versions, physical crates, holds, event receipts and an outbox. Enforce one live hold per crate and per request inside a database transaction. Use deterministic clocks in tests. Track contact identifiers only in the handset adapter when practical, and keep secrets and pilot mappings outside the source tree.

The browser opens directly into the local shortage. A phone thread shows the buyer's next action while a telex tray stays quiet until a buyer widens. The quiet tray and the incoming paper slip are the focal points. On mobile, the phone is first, with a labeled way to reach the room. Use plain language, clear focus, meaningful status announcements, and no dependency on animation. The simulation has no phone-number entry.
